What we can prove about Find_Orb

Machine-checked mathematical results, restricted translation validation of actual WASM, and source-based numerical experiments now support specific parts of the port. The investigation also reproduced and fixed two defects in the optional Prince–Dormand path.

The complete solver and compiler are not proved correct. Each result below identifies the proposition, domain, evidence, and remaining trusted boundary. A valid theorem about a model does not automatically verify its C++ implementation or physical accuracy.

Source-ordered ephemeris error bounds

The actual jpl_eph::interp() recurrence is modeled operation by operation, including its two separate position additions in the velocity recurrence. Lean proves the polynomial derivative relationships for every degree and the time-scale factors. The concrete proof follows all 1,084 operation-graph nodes and composes their rounding errors through to every output. Exact scope and source references.

3. Lean proof termsEvery predecessor error is used to derive the next node and final output bounds.
4. Raw kernel replayAll theorem dependencies rechecked; standard canonical axioms only.

The domain requires finite stored coefficients within scanned envelopes, normalized time in [−1,1], successful I/O and valid cache state, round-to-nearest ties-to-even, gradual underflow, and no reassociation or fused contraction. The rounding-function predicate uses unit roundoff 2−53 plus conservative absolute slack 2−100; all modeled intermediates stay below the finite guard. New Lean proofs derive this predicate from an explicit finite nearest-representable operation, including subnormals and binade carry. The finite binary64 field/word codec is proved bijective. Connecting an executed IEEE instruction to that mathematical operation remains an explicit implementation boundary. The WASM numerical specification supplies the intended operation semantics.

The 20 integer/array/cache SMT obligations include time-lattice index bounds and output disjointness. A failed-I/O counterexample shows why a cache invariant cannot be asserted unconditionally: upstream updates its cache index before a read succeeds. The port rejects that failed query; the proof assumes successful reads or previously valid hits.

Integrator proofs, counterexamples and fixes

Exact default-method conditions

The active source branch defines ORIGINAL_FEHLBERG_CONSTANTS. Its ideal rational coefficients pass the complete rooted-tree conditions through advancing order 5 and embedded order 4. Lean checks the individual stage identities and equations; the correspondence to method order uses the classical Butcher theorem.

The actual unsuffixed C++ constants are evaluated as binary64 before widening to WASM binary128. Their low-order residuals are small but nonzero. Treating stored floating-point coefficients as exact ideal coefficients would overstate the result.

Optional PD path corrected

An extra leading zero shifted derivative-stage times one slot early. For y′=t, y(0)=0, and one step of length 1, the original returns about 0.3286746718; the exact answer is 0.5. The corrected time array removes the defect. A separate patch releases the step workspace, previously leaked on every PD call.

The default Fehlberg selector is unchanged. Despite historical “8/9” naming, the PD coefficients correspond to the intended 8(7) pair; rounded coefficients are not an exact order-8 theorem. Netlib RKSUITE identifies the 13-stage pair with embedded order 7. The existing conservative step-growth threshold was retained.

A zero estimate cannot certify universal accuracy

Using the actual stored Fehlberg stage times ci, construct the smooth polynomial

q(t) = ∏i=1…6 (t − ci)²,   y′(t)=q(t),   y(0)=0,   t₀=0,   h=1.

Every sampled derivative and every weighted embedded estimate is zero. Lean proves an explicit antiderivative has a strictly positive endpoint, approximately 3.9358535586×10−7. The actual extracted compiled step also returns zero state and zero error norm. Therefore no finite multiple of the embedded estimate can bound true local error for every smooth RHS. This example does not purport to be the astronomical force model.

Validation of actual compiler output

The validator extracts unchanged source functions, parses Clang's actual AST, decodes WASM bytes independently, and compares symbolic memory effects and return values. It validates O0/O3 versions of dot_product, vector_cross_product, vector3_length and normalize_vect3. Only the cross-product has an identifiable retained body in the current production binary; the other extracted proofs do not establish production-call-site equivalence.

All 10 positive obligations are UNSAT in Z3 4.15.4 and cvc5 1.3.4. The source normalizer's sqrt(d²) != 0 branch is actually optimized to d² != 0; its IEEE lemma is checked for every binary64 input. A sound congruence overapproximation handles identical arithmetic terms without replacing universal validation with sampling.

The modeled domain includes signed zero, subnormals, infinities and NaN classes, valid aligned disjoint arrays, and unobserved scratch stack storage. NaN payload/sign, overlapping arguments, floating-point exception state, arbitrary memory effects and unsupported opcodes are outside scope. Four changed binary bodies produce SAT witnesses in both solvers and observable changes when replayed in Node; four invalid/unsupported cases and ten checker regressions test rejection.

The trusted base includes extraction, Clang's AST, both custom interpreters, binary decoding, memory abstraction, congruence substitution and the two solvers. Solver agreement is independent implementation corroboration, not an independently kernel-checked SMT proof. No Alive2 run or whole LLVM/Binaryen/compiler-rt proof is claimed. Retained production interpolation and runtime

The actual jpl_state binary contains an inlined interpolation slice. Its 1,806 unchanged bytes are selected structurally and decoded directly. The source model and production interpreter agree across 14,796 finite control/cache configurations while coefficient and cache values remain symbolic. Subinterval addresses use a separately checked affine model. The actual selection guard, unrolled recurrence loops, memory accesses and observable outputs are checked. An additional 5,265 setup correspondences check supported body/pointer-slot mappings. Seventeen interpreter regressions exercise rejection and control semantics.

All 114 profile/component/quantity output expressions match the existing rounded-operation certificate for recomputed interpolation. This connects the numerical DAG to retained production operations under the stated slice entry, input, coefficient-envelope, and rounding assumptions. The checker does not prove every caller reaches the slice with those assumptions. Warm numerical-cache correctness, I/O, date conversion, later body/unit transformations, and physical accuracy retain their own boundaries.

Operand commutation is justified by 12 supporting dual-solver obligations, including explicit classified add/mul rules. Direct SMT floating-point commutativity attempts timed out and are not counted as proofs; transfer from the reviewed classified rules to IEEE instructions remains trusted. Three changed production slices fail with executable WASM witnesses; memory and unsupported-opcode controls also reject. Exact slice domain, evidence and trusted base.

Binary128 conversion and shift routines

Four complete retained runtime functions are interpreted directly from the same shipping binary: __ashlti3, __lshrti3, __extenddftf2, and __trunctfdf2. For all input bits within their memory/shift preconditions, the proofs establish path coverage, memory bounds, result refinement, unchanged memory outside output/scratch regions, and restored stack globals. The bit-field specifications cover subnormals, signed zeros, overflow and explicit NaN payload handling; binary64 widening/narrowing round-trip behavior is checked too.

Seventeen obligations use normal bit-vector/array solver modes. Two additional field-specification/IEEE-conversion bridges require cvc5 experimental FP128 support, documented by cvc5 as having known issues. Both also pass Z3, but neither is an independently kernel-checked certificate. This qualification does not apply to the direct instruction-to-bit-field proofs. Eleven interpreter regressions, 310 finite executions, and four dual-SAT mutations with actual production-body execution witnesses check the tooling.

The remaining runtime arithmetic, including binary128 addition, multiplication, division and general square root, is not proved. Nor is there a proved semantic connection from these solver-checked conversions to the Lean rounding definition. What would extend the proof boundary

  1. Connect executable semantics to the proved rounding model. The finite-format rounding bound is now derived. Formalize the remaining interpreter and IEEE operation correspondence, prove warm-cache invariants and slice entry conditions, and connect the solver-checked runtime specifications to Lean.
  2. Validate retained production integrator bodies. Extend the current interpolation-loop and runtime-conversion work to binary128 arithmetic, solver calls and allocation; establish every caller's memory, dimension and controller preconditions.
  3. Prove force-model bounds on explicit domains. Bound truncation and stability away from singularities, add validated event handling near close encounters, and propagate certified intervals through adaptive integration.
  4. Cover fitting and physical uncertainty. Nonlinear convergence, rank deficiency, covariance calibration, observation errors and ephemeris uncertainty need separate specifications and evidence.

The current results provide reusable foundations and expose concrete defects. They do not justify removing accuracy checks or silently lowering precision.
