What stays exact

JPL stores its ephemerides as Chebyshev coefficient records. The extractor follows the record-selection approach in Bill Gray’s original sub_eph utility: copy complete records and constants, then update the date headers. All planets, lunar data, and available additional quantities remain present.

The output contains 459 original records of 8,144 bytes each, plus the two header/constants records. Full-file SHA-256 verification precedes extraction. Tests compare the entire coefficient region and constant record byte for byte.

The native reader comparison covers 2,859 epochs: every record midpoint, all internal boundaries and their immediate floating-point neighbors, and 1,024 reproducible random epochs. It evaluates all 13 bodies/centers and the additional JPL quantities in position and velocity modes. Across 989,214 calls per file, 5,866,668 returned components agree bit for bit. Missing quantities return the same error codes.

Seven actual WASM cases also produce identical scientific output: a short observation arc, a held-out Ceres fit, heliocentric propagation, topocentric ephemerides, and three high-eccentricity orbits. Only wall-clock creation metadata is excluded from comparison. These checks provide strong regression evidence; they are not a formal proof of the complete solver.

The coverage contract

Every actual JPL query must satisfy 2451504.5 < JD ≤ 2466192.5.
Equivalent TDB calendar labels: after 1999-11-22 00:00:00 through 2040-02-08 00:00:00. The requested useful window is 2000-01-01 through 2040-01-01.

The lower endpoint is excluded because the original reader uses the preceding record at exact internal boundaries. The cropped file cannot reproduce that convention at its very first timestamp. One additional record on each side protects the requested interval.

All evaluation paths are guarded inside the compiled planetary-position routine. Missing ephemerides, an out-of-range integration or light-time epoch, and read failures terminate the command. The analytic fallback cannot silently substitute approximate planetary coordinates. Five actual WASM failure tests exercise both interval edges, the excluded lower endpoint, a truncated reader, and missing data.

Time coverage applies to intermediate calculations as well as user-entered dates. Some otherwise in-range jobs can still leave the window during integration. Such jobs require a larger pack.

Why the default includes 2000 instead of starting in 2020

Upstream miscell.cpp: make_fake_astrometry() creates a dummy observation at 2000-01-01 when loading an existing state vector with -o. The observer position is evaluated before that placeholder is replaced by the requested epoch. A 2020–2040 pack failed this path, correctly, under the strict guard. The default therefore preserves the upstream behavior and includes J2000. The distribution generator rejects custom spans that cannot initialize this command mode.

Use an automatic, verified download

Host dist-compact/ with your application and pin its manifest in the application build. The loader verifies the worker and decompressed pack against the manifest before executing anything. The normal browser cache can retain the compressed assets; an offline application can precache the same files.

import { createSessionFromUrls } from 'find-orb-wasm';

const session = await createSessionFromUrls({
  workerURL: '/find-orb/find-orb-worker.js',
  dataURL: '/find-orb/find-orb.data.gz',
  manifest: trustedManifest,
  compression: 'gzip'
});

Automatic fetching removes the upload step. It does not remove the physical information needed for planetary perturbations. Embedding the same data as base64 would enlarge the JavaScript asset and duplicate parsing/memory costs; a cacheable verified asset is the current approach.

Reproduce the checks

Prerequisites: a built strict candidate in dist/, its pinned upstream sources, the checksum-verified full DE440 file in .cache/, Node, and Clang. The output directory must be new; extraction will not overwrite an existing distribution.

node data/compact.mjs
node data/verify-native.mjs
node data/verify-wasm.mjs
node --test tests/data/*.test.mjs
node data/report.mjs

Missing prerequisites fail visibly. The native compiler identity, pins, hashes, coverage details, sizes, and WASM guard results are recorded in results/dataset.json.
